## Learning Gate (Standard + High-stakes)

- A committed, scheduled usability test: study type · participant criteria · task list · success thresholds · named owner · due date. Record in `dashes/{slug}/research-plan.md`.
- Live instrumentation: success-metric events should reference a real production ticket when one exists, not only prototype `console.log`s.
- Every open assumption in `assumptions.md` mapped to a validation method.
- Sign-off ledger (in `scope.md`): each Responsible discipline row is `✅ real` (Standard) or all Responsible rows `✅ real` (High-stakes). `⚪ simulated` rows become evidence debt.
- High-stakes: instrumentation + all-real sign-offs must be confirmed before the dash is marked complete.

**Unassigned owner — a defined debt state, not a pass.** The gate wants a named owner and a due date. A solo run has no one's calendar to commit and no researcher in the loop, so it has two dishonest options and one honest one. The honest one is defined here:

| Condition | State | Gate result |
|---|---|---|
| Real named owner + real due date | committed | Gate **passes** |
| `session-mode: solo`, Standard tier, no real human owner exists | `owner: unassigned — needs human` | Gate records **⏳ debt** — it does **not** pass |
| High-stakes tier | not available | High-stakes requires a real owner. A solo High-stakes dash has already halted (see P0) |

The unassigned state exists because solo mode has no human to ask. **An interactive dash must ask.** If the designer declines to name an owner, that is a decision by a reachable human, not an absent one: record a `⏳ debt` row against the research discipline naming who declined and why, and the gate still does not pass. Do not reach for the unassigned state to avoid an awkward question.

When the unassigned state applies:

1. **Write the whole plan anyway.** Study type, participant criteria, task list, and success thresholds must all be complete and executable in `research-plan.md`. Only the owner and the due date may be unfilled — they are the two fields that require a human, and nothing else gets to hide behind them.
2. **Use the literal strings.** `owner: unassigned — needs human` and `due-by: unassigned — set when owner is named`. Verbatim, so the state is greppable and cannot be mistaken for a missing field.
3. **Never invent an owner or a date.** Not a plausible-sounding name, not a placeholder person, not the dash author unless the dash author is a real human who agreed in session. An agent is not an owner.
4. **Log it as debt.** Add an `assumptions.md` row with `status: debt`, and a `⏳ debt` row in the sign-off ledger against the research discipline.
5. **Report it as debt, everywhere the gate is reported.** The `workshop-summary.md` Learning Gate row is `⏳ debt`, never `✅`. The living-plan `<GateStatus name="Learning Gate">` result is not `pass`. The pitch site does not claim a scheduled test.
6. **The dash may close as complete-with-debt.** It may not be described as having cleared the Learning Gate. Say which one it is in the handoff brief, in those words.
7. **The learning-close SLA clock does not start.** The 15/30-business-day window in `skills/7-critique-testing/learning-loop/SKILL.md` runs from the moment a real owner and date are recorded, not from the dash close.

**Learning-close** (tracked, not in-session): within 15 business days (Standard) or 30 (High-stakes), the named owner records test-ran (y/n) + assumptions-validated (count). A miss flips Quality 3 to the capped grade.
