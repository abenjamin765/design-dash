### Subagent brief contract — Concept divergence + adversarial panel (P5)

**Main thread passes:**
- `slug`, tier, `session-mode` (`interactive` | `solo`), hub object (name + slug), flow summary (from P4 return — 3-sentence scenario + page list), user success criteria, business metric to score against

**Subagent writes to disk:**
- `dashes/{slug}/living-plan/phases/p5.mdx` (ConceptCompare / ConceptCard blocks, distinctness check, selection rationale, gate status)

**Workshop `.md` files are exporter output for §1–§3 of `design-spec.md`.** Do **not** rewrite those sections. After export, the main thread (or subagent, if asked) may hand-author `## Selected Concept` (§5) into `design-spec.md` — that section is preserved across exports. Prefer writing the living-plan file first; §5 is a summary pointer, not the source of truth.

**Subagent returns to main thread (cap 1k tokens):**
- Scored concept table: concept name | hub object | primary surface | user score | business score | recommended

**Subagent runs:** Load `skills/4-synthesis-ia/concept-divergence/SKILL.md`. The sub-skill generates 2–3 structurally distinct design concepts (different hub object, flow spine, or primary action) and scores each on user success criteria + a business metric. Load `skills/7-critique-testing/adversarial-panel/SKILL.md` to pressure-test concept distinctness and challenge each concept from persona perspectives.

---

**Selection Gate**: concept selection requires scoring against **both** user criteria and a business metric. Concepts must be verified as structurally distinct by the panel (cosmetic variants fail). Engagement / time-in-app / streaks may not be the deciding business-case metric when the primary audience is minors or other vulnerable populations (see ethics Section B). Record the chosen concept, the runner-up(s), and the scoring rationale in `p5.mdx`.

*Express skip*: Selection Gate deferred. Proceed with the single strongest concept; log the skip as evidence debt.
