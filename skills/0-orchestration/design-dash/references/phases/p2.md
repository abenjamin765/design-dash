# P2 — Intake & Object Modeling

Detailed source for this phase. See also the orchestrator summary in `SKILL.md`.

In **interactive** mode: WAIT FOR USER between every checkpoint. In **solo/auto** mode: auto-confirm and log; pause only if a GATE fails or a clarifying question is blocking. Capture answers to `scope.md` as you go.

## 2.1 Problem statement + scope
Ask: what problem are we solving and what is the scope? Capture in 1–3 sentences; push back on vague statements with one clarifying question.

## 2.2 User role
Ask for the primary role (e.g. end-user, operator, admin, or domain-specific labels the team uses). Record literally; describe if "other."

## 2.3 Build mode
Ask: new · enhance · refactor. For enhance/refactor: verify the existing prototype or product path exists when one is claimed.

## 2.4 Solo or group?
If group: ask 2.4a (duration), 2.4b (OOUX-new audience? → triggers variant in P3/P6), 2.4c (remote/in-person), 2.4d (participant list). If group, load `skills/0-orchestration/facilitation-kit/SKILL.md`, then write `dashes/{slug}/meeting-invite.md` from `references/meeting-invite-template.md` using the 2.4a–2.4d answers — do not re-ask for inputs already captured.

## 2.5 Constraints
Capture as bullets; "None stated" is valid.

## 2.6 Success criteria
Must be concrete and checkable. Push back on unmeasurable criteria with: "What would the user be doing if it was working?"

### GATE — product alignment
Is there product alignment on what we're solving? No → STOP; recommend product alignment first. Ambiguous = no.

## 2.7 Page-scoping mode
Journey · object (surface `hub-object` microlearning on first use) · named. When scoping to a **named page**, or when build mode is **enhance/refactor**, seed collections, CTAs, and attributes from existing object guides in `library/objects/` and any page notes already in scope — do not invent them.

## 2.8 Library queries — local object library (Standard / High-stakes)

**Object library path:** `library/objects/{slug}.md` (plus `library/objects/_index.md`). Load `skills/_cross-cutting/object-library-context/SKILL.md`.

**Express**: run library queries in the main thread — digest-level reads from `_index.md` and short guide sections; full `Read` for the hub object only.

**Standard / High-stakes**: dispatch library research as a subagent when useful.

### Subagent brief contract — Library research (2.8)

**Main thread passes:**
- `slug`, hub object name(s), in-scope roles, path to `library/objects/`

**Subagent writes to disk:**
- Maturity table (and per-object digest notes) into `dashes/{slug}/living-plan/phases/p2.mdx` under the Objects / library-research section the phase already uses

**Workshop `.md` files are exporter output.** Do **not** append the maturity table to `scope.md` directly — the main thread runs `cli.mjs export` at the phase boundary when living-plan is active.

**Subagent returns to main thread (cap 3k tokens):**
- Maturity table (object | slug | maturity | audited date | warning)
- Per-object digest: slug · maturity · audited date · one-sentence identity · top 3 prioritized properties · key relationships

**Subagent runs:**
Read `library/objects/_index.md`, then digest sections from each in-scope guide. Full `Read` for the hub object only. Surface `nom` microlearning on first use. Never invent attributes, CTAs, or relationships — log gaps in `assumptions.md`.

**Maturity table (mandatory — emit before leaving 2.8):**

| Object | Slug | Maturity | Audited | Warning |
|---|---|---|---|---|
| … | … | canonical / needs-review / draft | YYYY-MM-DD | e.g. do not invent attrs on needs-review |

Flag `draft` maturity, stale guides, missing prioritized properties. Designer must explicitly confirm any `draft` or `needs-review` object used as a hub.

If audited dates are missing, say "staleness unverified — no audited date in guide" rather than inventing one.

## 2.9 Dual mental-model capture
For each in-scope object, capture: (a) what the user expects/knows about this object (tag each element `observed` or `assumed`), and (b) the **system model from the local object library** (`library/objects/`). Record both in `scope.md` § Mental models.

**Mental models are owned here.** Later phases read them; they do not re-author a competing mental-model table.

## 2.10 Existing-state review (branch on build mode)
new → skip · enhance/refactor → read existing UI/prototype HTML when available, summarize state + pain points.

## 2.11 Supporting docs review
Figma URLs, briefs, screenshots, research notes. "None stated" is valid.

## 2.12+ Object modeling
Load skills from `skills/3-object-modeling/` as needed: object discovery → NOM → CTA matrix → object map → object guides → `artifact-validator`.

Write guides to `library/objects/{slug}.md` and update `library/objects/_index.md`.

**FORK**: if library has gaps that block design → run a focused library-gap pass (document gaps + proposed guide stubs); return with findings.

**Output**: `dashes/{slug}/scope.md` (full intake + library findings + mental models + assumptions notes); object guides; `living-plan/phases/p2.mdx`.
