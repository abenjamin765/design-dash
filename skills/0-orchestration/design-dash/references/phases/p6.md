## Ethics portion (6.5–6.7 + gate) — main thread only

> **The ethics Section C review runs in the main thread. Never delegate it.**

Section C must run item-by-item with a cited design decision per item. It is the confirming authority for the tier; delegating it would break that guarantee.

### Critique portion (6.5–6.7)
6.5 Success-criteria check · 6.6 P/S/T/Q hierarchy fidelity (surface `pstq-ranking` microlearning on first use) · 6.7 Accessibility (WCAG 2.1 + 2.2 AA). Optional: load adversarial-panel persona review.
6.7b **Heuristic evaluation** — load `skills/7-critique-testing/heuristic-evaluation/SKILL.md` when present (optional Standard; recommended High-stakes). Append findings to `dashes/{slug}/critique.md`. Also run the short P6.D checklist in `references/critique-checklists.md` when present.

**Ethics Gate (mandatory for all tiers)**:
- Render edge states in the wireframe for each page: empty · loading · error · permission-denied · content-at-scale (not one-liners — visible in artifact).
- Render the **per-row data-confidence state** for any page that lists records carrying a derived, predicted, inferred, or aggregated per-record value: what a single row shows when the data behind it is insufficient, stale, or below its confidence floor, while the rest of the view is fine. This is a distinct state from the page-level empty state; record the threshold that triggers it, the label shown, and the value the design deliberately withholds. `N/A` is valid only with a stated reason.
- When the selected concept is a **pushed surface** (digest email, notification, chat message, SMS), three columns have no runtime moment: there is no loading state, no denial screen, and "empty" is a send-or-suppress decision. Use generation-time equivalents — same intent, labelled in the cell. Do not invent a second matrix shape and do not leave the columns blank.
- Load `skills/7-critique-testing/ethics-equity-review/SKILL.md`. Each ethics/equity item must cite a specific design decision. In **solo** mode, self-answer from config/artifacts; do not shorten Section C.
- For Express tier: ethics floor only (dark patterns + vulnerable-population motivation guardrails).
- For Standard/High-stakes: full matrix including localization, performance/bandwidth, age/context appropriateness.
- When the design touches personal data or PII: run privacy checklist items (consent path · data minimization · retention/deletion · role-based access · no third-party sharing without appropriate agreement). Triggers Privacy gate — load `skills/7-critique-testing/privacy-gate/SKILL.md`.
- Run `a11y-audit`.

**Section C is the confirming authority for the tier.** Run Section C item by item with a real cited design decision per item — never as a summary judgment, and never skipped because P0 already decided. Then reconcile it with the provisional P0 tier per **The P0 tier is provisional** in P0:

- **Any Section C flag → raise to minimum High-stakes** with real privacy/legal sign-off. No simulation floor. A Section C flag cannot be waived, argued down, deferred as debt, or cleared by the adversarial panel. Follow the privacy-gate escalation path.
- **Zero Section C flags → the provisional tier is confirmed**, and may be lowered only if P0 fired T1 alone and a non-author reviewer confirms the finding. Record any change in `tier-override-log`.
- Record the Section C outcome explicitly in the gate summary even when it is zero flags — "zero flags" is the evidence that confirms the tier.
- Solo dashes: a raise to High-stakes here halts the dash at P6. Write the P6 artifacts, log the raise, and stop — see **Solo mode and the tier ceiling** in `references/phases/p0.md`.

Gate fails → loop back to 6.1.

**Output**: `wireframe.html`; `ethics-review.md`; `living-plan/phases/p6.mdx`.
