# P0 — Preconditions + Tier Classification

Detailed source for this phase. The orchestrator summary lives in `skills/0-orchestration/design-dash/SKILL.md`; follow this file for checkpoint depth.

## Workspace contract (run first)

Detect where the dash is running and record in `dash-config.yaml`.

| Check | How | Action |
|---|---|---|
| Artifact root | Default `dashes/{slug}/` unless `artifact_root` is set | All workshop artifacts land here |
| Object library | `library/objects/` exists (guides + `_index.md`) | Load `skills/_cross-cutting/object-library-context/SKILL.md`. List relevant objects. Never invent attributes — log gaps in `assumptions.md` |
| Optional prototype workspace | `prototype_workspace` set in config or asked at P0 | P7 may write a coded prototype there when a design-system base page is resolvable; otherwise P7 is **stub mode** |
| Living-plan CLI | `apps/dash-living-plan/cli.mjs` exists and Node is available | Seed + serve (soft-fail viewer). If missing, use `method.yaml` capability fallback `no_node_runtime` and author workshop markdown from templates |

**Do not invent a proprietary design-system tree inside this repo.** An unresolvable prototype base means P7 stub mode, never a locally scaffolded product design-system tree.

Also set session mode: if `/design-dash --solo` or `--auto`, write `session-mode: solo` and explain auto-confirm rules; otherwise `session-mode: interactive`.

## Precondition checks (run before everything else)

1. **New or resume?** Ask: "Is this a new dash, or are you resuming one?" If resuming → load `skills/0-orchestration/design-dash-revision/SKILL.md` and exit the orchestrator skill.
2. **Object library**: confirm `library/objects/` is readable. Soft-warn if empty or missing indexes; guide the designer to add guides or note domain objects as `assumed` in `assumptions.md`. Hard-stop only if the designer requires library grounding and no path exists.
3. **Workspace dirty**: `git status` in the current working tree. If unrelated dirty files exist, note them once — do not block on multi-project noise.
4. **Research access (Standard/High-stakes)**: confirm an evidence path via `evidence-assembly` — research notes, analytics links, Confluence/docs, or a local evidence pack. No proprietary research MCP is required.
5. **Solo or group?** If group → load `skills/0-orchestration/facilitation-kit/SKILL.md`.
6. **Tier classification**: run the trigger checklist below. Record tier in `dashes/{slug}/dash-config.yaml`.

## Tier classification (rule-derived, not self-selected)

Run this checklist. The highest trigger wins. Record `tier` (or `dash_tier`) and `computed-tier-rationale` in `dash-config.yaml` — the rationale is how P6 confirms or raises this tier later, so a bare tier name is not sufficient.

| id | Trigger (any one forces the minimum tier shown) | Minimum tier |
|---|---|---|
| T1 | New disclosure of regulated personal data / PII (GDPR, HIPAA, CCPA, COPPA, or equivalent) | **High-stakes** (+ Privacy gate) |
| T2 | Payment / financial / health / assessment-scoring surface | **High-stakes** |
| T3 | Reach ≥ 10,000 users OR multi-tenant / enterprise-wide rollout | **High-stakes** |
| T4 | Irreversible or hard to roll back; affects a core business workflow | **High-stakes** |
| T5 | Affects > 1 user role, OR reach 500–9,999 users | **Standard** |
| T6 | Reach < 500, single role, reversible, no PII | **Express** (floor) |

**Reading T1.** T1 asks whether the design creates a **new disclosure**, not whether personal data merely appears on screen. Re-presenting a value the same role could already see elsewhere is usually existing authorized access, not a new disclosure. What does fire T1: a role can now see identifiable data it could not before; data crosses a role boundary; a new identifiable field/linkage is created; retention/storage/deletion changes; a new export/share/integration path opens.

**T1 is a tier rule, not a privacy exemption.** Narrowing T1 changes *which tier the dash starts at*. It does not change whether privacy is reviewed:

- The **privacy-gate trigger screen still runs at P0** whenever the design touches personal data. Load `skills/7-critique-testing/privacy-gate/SKILL.md` and run its Step 1 screen; record the outcome in `scope.md`.
- The **P6 ethics Section C review runs at full depth** regardless of tier, and it is the authority that confirms this tier (below).
- **Uncertainty escalates.** If you cannot tell whether a disclosure is new, treat it as new and fire T1. Write the reasoning into `computed-tier-rationale` either way.

**Express defers, never deletes.** Every gate Express skips becomes a dated entry in `dashes/{slug}/assumptions.md` with a validation method. **The designer may escalate the tier, never lower it.** For High-stakes, a reviewer who is not the dash author confirms the tier.

Emit the tier prominently, name the trigger id that set it, say that it is provisional, and list which gates are mandatory for this session.

## The P0 tier is provisional — P6 Section C confirms it

P0 classifies from a description of the design. P6 Section C of the ethics review reviews the design itself, item by item, with a real design decision cited per item. Section C is therefore the **confirming authority** for T1, and the P0 tier is **provisional** until it runs.

| Section C outcome | Effect on the tier |
|---|---|
| **Any** Section C item flagged | Tier is **raised** to minimum High-stakes and real privacy/legal sign-off is required. No simulation floor. This cannot be waived, argued down, deferred as debt, or traded against a deadline — see P6 |
| Zero flags · tier is High-stakes · **T2, T3, or T4 fired** | **No change.** Section C has no authority over payment/reach/reversibility. The High-stakes tier stands |
| Zero flags · tier is High-stakes · **T1 fired and T2–T4 did not** | The provisional tier **may be lowered** — to Standard if T5 fired, to Express if only T6 applies. Requires a non-author reviewer's confirmation and a `tier-override-log` entry. If no reviewer is available, the tier stays High-stakes |
| Zero flags · tier is Standard or Express | **Confirmed final.** Record the zero-flag finding; the tier stops being provisional |

Rules that hold in every case:

1. **A Section C flag only ever raises.**
2. **Lowering requires a non-author reviewer.** No reviewer available → the tier stays where P0 put it.
3. **Record it, do not overwrite it.** Any change writes a new `tier-override-log` entry in `dash-config.yaml`.
4. **Gates already run stay run.** Lowering at P6 does not retroactively un-run P1–P5.
5. **Raising at P6 applies the full High-stakes gate set**, including earlier-phase gates as debt with owner + due-by if the phase has passed.
6. **A new data surface discovered mid-dash re-runs P0's T1 screen** at that moment, not at P6.

## Solo mode and the tier ceiling

**Solo mode caps at Standard.** High-stakes requires every Responsible discipline `✅ real` before P8 and a non-author reviewer to confirm the tier. A solo run has neither by construction.

**If the tier is High-stakes and `session-mode: solo`, halt at P0.** Fail here, where it is cheap, rather than at P8 after the work is done.

1. Do not proceed to P1.
2. Write **only** `dashes/{slug}/dash-config.yaml`, as the halt record: `tier: high-stakes`, `session-mode: solo`, the trigger id and `computed-tier-rationale` that produced the tier, and `halted-at: P0` with the reason.
3. Write nothing else — no other workshop artifact, no seeded living plan, no phase marked in progress. There is no partial dash to resume from; the next run starts at P0 in interactive mode and may overwrite this config.
4. Announce: "P0 halt — this dash classified {trigger id} → High-stakes, and High-stakes cannot be run solo. Re-run interactively with real participants named for every Responsible discipline, plus a non-author reviewer to confirm the tier."
5. Name what the interactive run needs: a named human per Responsible discipline in the sign-off ledger, a non-author tier confirmer, and — if the escalation came from T1 — a real privacy/legal reviewer.

Three things are **not** ways around this halt:

- **Running Section C early does not unlock a solo High-stakes run.** Lowering a provisional tier needs a non-author reviewer, which solo does not have.
- **Switching `session-mode` to `interactive` in the config file does not make the run interactive.** Interactive means real humans answering at checkpoints.
- **The designer cannot waive it.** Offer the interactive re-run, or offer to narrow scope so it no longer fires a High-stakes trigger — and if the scope narrows, re-run the whole P0 classification.

The same ceiling applies **mid-dash**: if P6 Section C raises a solo dash to High-stakes, the raise stands and the dash halts at P6 under the same rules — record the raise in `tier-override-log`, write the P6 artifacts already produced, and stop. Do not finish P7–P8 at High-stakes solo.

## Express-light path (when `tier` = express)

Express uses a **minimum artifact set** — do not load full Standard sub-skill depth unless the designer escalates:

| Phase | Express minimum | Skip / defer |
|---|---|---|
| P1 | Short problem + `assumptions.md` debt for Evidence Gate | Full evidence sweep optional |
| P2 | Intake + library query (`library/objects/`) + mental models + light object model | Full library-gap workshop unless gaps block design |
| P3 | Problem lock + objects + light sign-off + `design-spec.md` §1–3 | Full RACI for every discipline |
| P4 | **1 primary scenario** + page list in `flow.md` (orchestrator may write directly) | Full `scenario-flow-mapping` optional; Reconciliation → debt |
| P5 | **1 strongest concept** recorded in scope/spec | `concept-divergence` + adversarial panel unless designer asks |
| P6 | Wireframe + ethics **floor** + edge states visible | Full ethics matrix → debt if escalated later |
| P7 | Stub note (or optional coded prototype if workspace set) | — |
| P8 | Pitch site + workshop-summary | Learning Gate → debt |

Target: Express agent-run completes in roughly one focused session without Standard ceremony.

**Output**: `dashes/{slug}/` folder created; `dashes/{slug}/dash-config.yaml`. Seed living plan when Node is available.
