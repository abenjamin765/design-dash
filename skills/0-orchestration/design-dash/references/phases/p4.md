# P4 — Flow & Reconciliation Gate

Detailed source for this phase. See also the orchestrator summary in `SKILL.md`.

**Express**: write one primary scenario, the Urgency/flow steps, and a page list into `living-plan/phases/p4.mdx` — do **not** require loading full `scenario-flow-mapping` unless the designer wants depth. Log Reconciliation Gate as evidence debt. Run `export` at the phase boundary; do not hand-author `flow.md`.

**Standard / High-stakes**: dispatch the scenario-flow-mapping as a subagent.

### Subagent brief contract — Scenario flow mapping (P4)

**Main thread passes:**
- `slug`, tier, `session-mode` (`interactive` | `solo`), hub object (name + slug + maturity), user role, problem statement, scope summary, `assumptions.md` path, in-scope object digests from P2 (`library/objects/`), path to `living-plan/phases/p2.mdx` (or exported `scope.md`) Mental Models section from 2.9

**Subagent writes to disk:**
- `dashes/{slug}/living-plan/phases/p4.mdx` (scenarios, flow, page list, goal-page map, reconciliation, constraints, gate status)
- Appends any new assumed rows that need tracking to `dashes/{slug}/living-plan/phases/p1.mdx` Assumptions (or logs them for the main thread to add) — never invents evidence

**Workshop `.md` files are exporter output.** Do **not** write `flow.md` or patch `design-spec.md` §4 directly. The main thread runs `cli.mjs export` at the phase boundary; that regenerates `flow.md`. Hand-authoring `design-spec.md` §4 (Scenarios & Flow summary) is a main-thread step after export, if needed.

**Subagent returns to main thread (cap 2k tokens):**
- Primary scenario summary (3 sentences)
- Page list (names only)
- Reconciliation findings (divergences as bullet list — user model vs. local object-library system model, each with a resolution direction)

**Subagent runs:** Load `skills/4-synthesis-ia/scenario-flow-mapping/SKILL.md`. The sub-skill owns checkpoints 4.1–4.7.

---

**Reconciliation Gate** (Standard + High-stakes): after flow is complete, surface every divergence between the user mental model (from 2.9 / `scope.md` Mental Models) and the system model from `library/objects/`. For each divergence record: adapt UI language to user model, OR raise a library change proposal (guide update / open question). No `assumed` user-model element may drive an irreversible decision without a P8 test commitment flagged in `assumptions.md`. Resolution-direction: prompt if library-change-proposals = 0 (possible rubber-stamp). The gate lives in checkpoint **4.7** of `scenario-flow-mapping` — do not treat the template comment alone as the rubric.

Optional: `nav-flow-designer` for a navigation blueprint.

**Output**: `living-plan/phases/p4.mdx` → export produces `dashes/{slug}/flow.md` (scenarios, flow steps, page list, goal-page map, reconciliation, constraints). Optionally hand-author a short §4 summary into `design-spec.md` after export (preserved below the exporter banner).
