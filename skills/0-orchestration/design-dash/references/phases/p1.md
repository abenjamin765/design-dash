# P1 — Opportunity & Evidence *(Evidence Gate — Standard + High-stakes)*

Detailed source for this phase. See also the orchestrator summary in `SKILL.md`.

**Purpose**: Validate that the problem is worth solving before committing design effort. Assemble existing research and baseline metrics.

## 1.1 Problem statement structure
Ask the designer to provide (or draft together):
- Current state · affected role · evidence (source + link) · magnitude/reach (cited number) · cost of inaction · desired outcome · success metric · confidence (high/medium/low)

## 1.2 Opportunity sizing
Ask: `reach × value × confidence` — or a simpler "narrow/medium/broad reach + high/med/low value" if hard numbers are unavailable. Capture as `assumed` if no data, `observed` if research-backed.

## 1.3 Evidence assembly
Invoke `skills/2-research/evidence-assembly` to pull existing research notes, analytics, and BI. Tag each evidence item `observed | borrowed | assumed`. An `observed` tag requires an evidence link (session URL, note with participant count, transcript, ticket) — no bare attestation. No proprietary research MCP is required; offline packs and linked docs are valid.

## 1.4 Assumptions register
Initialize `dashes/{slug}/assumptions.md`. Each unvalidated decision becomes a row: id · statement · type · confidence · validation method · owner · status · linked decision.

## 1.5 Instrumentation hypothesis
Ask: what success metric would prove this design worked? Draft the first row of `dashes/{slug}/metrics.md` (metric · event/measure · source · baseline · target).

**Evidence Gate**: No stage advance without ≥1 evidence source **or** an explicitly tagged assumption with a scheduled validation method + opportunity sized. `observed` items must carry an evidence link; missing link auto-downgrades to `assumed`.

*Express skip*: Gate is deferred. Create `assumptions.md` with debt entry and note that Quality 1 confidence is capped until validated.

**Output**: `assumptions.md`, `metrics.md` (Standard+), `living-plan/phases/p1.mdx`.
