01

Install

Start a dash in three commands

Skills install as symlinks into your agent’s skills directory — one edit to any SKILL.md propagates to both agents. Nothing to build, nothing to host.

  1. Clone the repo

    Get the skills, templates, method contract, and the local object library.

    $ git clone https://github.com/abenjamin765/design-dash.git
    $ cd design-dash

  2. Install the skills

    Symlinks everything into ~/.cursor/skills/ or ~/.claude/skills/. Preview first with --dry-run; remove with --uninstall.

    $ ./install.sh --cursor   # or: ./install.sh --claude

  3. Run the orchestrator

    Open Cursor or Claude Code and type the slash command. It sequences P0–P8 and stops at hard WAIT FOR USER checkpoints — you approve every gate before work continues.

    # inside Cursor or Claude Code:
    > /design-dash
No Cursor or Claude Code? Paste adapters/generic/AGENT_PROMPT.md into any file-capable agent and attach the method and templates — or run it as a human-facilitated workshop with GETTING_STARTED.md. Missing capabilities have named fallbacks; no gate silently disappears.
02

Process

Nine phases, three movements

A dash is a sequence, not a vibe. Each phase produces named artifacts, and five gates stop the run until hard questions have answers.

Frame · P0–P3

Establish what’s real

  1. P0 Preconditions

    Classify tier from rules; set session mode; assemble the roster.

  2. P1 Opportunity & evidence

    A falsifiable problem statement, sized — every claim carrying an evidence label.

    Evidence gate
  3. P2 Intake & object modeling

    Capture the user’s mental model, then run ORCA: NOM, CTA matrix, object guides — prioritized with Kano evidence.

  4. P3 Framing lock

    Lock scope in design-spec.md, tied to the assumption register so creep stays visible.

Shape · P4–P6

From model to testable concept

  1. P4 Flow & reconciliation

    Scenario flows and page architecture; resolve where system and mental model diverge.

    Reconciliation gate
  2. P5 Divergence & selection

    Two or three structurally distinct concepts, scored on user and business value.

    Selection gate
  3. P6 Wireframe & ethics

    Monochrome wireframes with edge states; ethics, equity, privacy, accessibility review.

    Ethics gate
Prove · P7–P8

Commit, then learn

  1. P7 Optional build

    A coded prototype when a design-system base exists — or an honest stub note when it doesn’t.

  2. P8 Validate & learn

    Stakeholder pitch site, research plan, and workshop summary; wire the learning plan before anyone builds.

    Learning gate

Five gates, each one a question you must answer

Gates aren’t bureaucracy. Each forces “is this real, or is it assumed?” — and on High-stakes runs, none of them are waivable.

P1

Evidence

Is this problem real? What’s the evidence, and how big is the opportunity?

P4

Reconciliation

Where does our system model diverge from how users think — and how is each divergence resolved?

P5

Selection

Did we weigh genuine alternatives against both user and business value?

P6

Ethics / Equity

Are empty, loading, error, denied, and at-scale states designed — with no dark patterns, equity gaps, or privacy exposure?

P8

Learning

How will we know if this worked? Is a usability test plan in place?

You don’t pick your rigor — the work does

// tier is rule-derived: risk, reversibility, and reach decide. No tier-shopping.

Express

Low risk, easily reversible, narrow reach. Never grading, payment, PII, or compliance.

Ethics/equity floor only. Skipped gates become tracked evidence debt — deferred, never deleted.

Standard

Moderate risk, reversible with effort — a real workflow with bounded blast radius.

All five gates mandatory. Real sign-off from each responsible discipline.

High-stakes

Hard to reverse, broad reach — or regulated personal, financial, or health data.

All five gates plus a privacy-compliance review, none waivable. Simulated review never substitutes for accountable sign-off.

Every claim carries a label

The assumptions register tags each statement so readers can weigh it — and unvalidated beliefs cap quality grades until they’re tested.

observed
Measured in your context — interviews, analytics, usability sessions. Needs an evidence link or it gets downgraded.
reported
Documented elsewhere: studies, benchmarks, partner data. Can’t override what you observed yourself.
inferred
Reasoned from evidence rather than measured directly — labeled as such, so nobody mistakes it for data.
assumed
Believed, not yet supported. Allowed in — but it caps quality, carries a validation method, and never gets quietly deleted.
03

Artifacts

Every dash ends with files, not slides

A dash ends at a PLAN. When it’s done, these are on disk — portable Markdown, YAML, and HTML that open anywhere and hand off to anyone.

  • assumptions.mdEvidence

    Append-only register: every belief tagged by label, given a validation method and an owner.

  • metrics.mdEvidence

    North-star, guardrail, and vanity metrics — with instrumentation status stated honestly.

  • glossary.mdEvidence

    Term ↔ object ↔ code identifier ↔ UI label. Versioned, so language drift gets caught.

  • nom.mdModel

    The Noun-Object Model: extracted nouns become candidate objects with definitions.

  • cta-matrix.mdModel

    Every call-to-action mapped to the object it acts on — no orphan buttons.

  • object guidesModel

    One authoritative page per domain object, written to library/objects/ where they accumulate.

  • flow.mdSynthesis

    Scenario flows and page architecture derived from the object model, not invented on top of it.

  • prioritization-report.mdSynthesis

    Kano tallies, Better/Worse coefficients, RICE table, triage verdicts.

  • edge-state-matrix.mdCritique

    Empty, loading, error, permission-denied, at-scale — designed per screen, not discovered in QA.

  • ethics-equity-checklist.mdCritique

    Dark patterns, privacy exposure, localization, accessibility — checked at P6, not after launch.

  • design-spec.mdFrame

    Locked scope: context, goals and non-goals, primary user — protected from silent growth.

  • requirements.mdPlan

    Objects, flows, acceptance criteria, open questions — build-ready or it doesn’t ship.

  • pitch/index.htmlPlan

    The stakeholder deliverable: a self-contained pitch site of the validated plan.

  • wireframe.htmlPlan

    Monochrome, annotated, design-system-agnostic. Opens in any browser.

  • summary.htmlPlan

    The self-contained centerpiece: problem, decisions, requirements, guides, embedded wireframe.

Plus a sign-off ledger recording which gates passed with real accountable review versus simulated panel — so readers know exactly how much confidence to carry.

The object library

Objects accumulate. Agents can query them.

Object guides discovered during a dash are written to library/objects/ and stay there — indexed by _index.md, one authoritative page per domain object. The next dash starts from what the last one learned instead of re-deriving it.

For agents and tools, the object-graph-export skill compiles the library into library/graph.json — a schema-validated property graph any script or MCP tool can load, no prose-parsing required.

Who it’s for

Three audiences, one artifact set

Product designers

Run discovery that survives scrutiny. The method asks where your evidence comes from, makes you weigh real alternatives, and hands you artifacts you can defend in review — because every claim on them is labeled.

Engineers

Receive specs you can build from: object guides with attributes and actions, flows tied to those objects, edge states already designed, acceptance criteria in Given/When/Then. Open questions are listed, not hidden.

Agent operators

The orchestrator skill sequences all phases and stops at hard WAIT FOR USER checkpoints — the agent facilitates, you decide at every gate. Outputs stay in Markdown and HTML you own, never trapped in a tool.
